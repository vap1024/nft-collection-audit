# nft-collection-audit

Pre-mint NFT evidence scoring with a 7.0 gate and a retrospective 30-day price tracker.

[![CI](https://github.com/vap1024/nft-collection-audit/actions/workflows/tests.yml/badge.svg)](https://github.com/vap1024/nft-collection-audit/actions/workflows/tests.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Open-source edition of a toolkit I use in my own operation; all demo data is synthetic.

## What it does

- Resolves primary fixture records separately from marketplace claims; empty
  floor/volume fields under loud liquidity claims cost points.
- Scores disclosed mint terms, concentrated/circular volume, and contract-review
  findings in four equally weighted components, producing a reproducible 0–10 score.
- Applies the inclusive **>= 7.00** candidate gate and explains every component
  in a collection card with source identifiers.
- Matches post-mint prices to 12 scheduled targets, showing percentage changes,
  actual sample times, and sampling offsets through day 30.

## Quickstart

Start in an **empty directory**, with Git and Python 3.11+ available. Three
commands, using a selected Python environment:

```text
git clone https://github.com/vap1024/nft-collection-audit.git .
python -m pip install -r requirements.txt
python examples/run_demo.py
```

The demo prints the report and writes `examples/output/scorecards.md`.
Use `--output other-folder/scorecards.md` to choose another local destination.
The application itself needs only the standard library; pytest is for tests.

As of 2026-10-24, the public clone line is prepared for publication scheduled
for 2026-10-27. The install/demo steps have been checked from a fresh **local**
clone. Public-clone availability is still pending; see [verification](VERIFICATION.md).

## Tests

```text
python -m pytest
```

**78 passed** locally on Windows, Python 3.13.15, pytest 9.1.1. Cases cover
collection gates, missing/misrepresented evidence, actual component inputs on
both sides of 7.0, output disclosures, invalid inputs, tracker matching, and
repository-file checks. Run `python tools/check_repository.py` for the latter.

CI is configured as one Ubuntu job on Python 3.11, including tests, sample
regeneration, and repository checks. The CI badge is a live status link; no
hosted run has been completed or claimed before publication.

## How Codex is used

**Codex as an independent auditor** is the workflow role: the author delegates
implementation and accepts results by checking the files and running the tests.
In this project, built with Codex, claims are checked against named synthetic
primary records, deductions remain inspectable, and the generated report must
match the disk fixtures. Local fixture checks do not establish external
marketplace, contract, or ledger facts. The documented review/fix is evidence
for this workflow; it is not a third-party assurance statement.
